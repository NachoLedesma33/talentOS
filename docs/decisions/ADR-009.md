# ADR-009 — Datos sintéticos y modo mock para desarrollo y demostración

Fecha: 2026-11-23
Estado: Aceptado

## Contexto

El principio SDD 1.2 exige «la aplicación debe poder ejecutarse en modo demo sin credenciales de servicios pagos». RNF-017 repite el requisito; SDD 6.2 añade que el modo demo debe funcionar localmente con mocks y fixtures y que no se debe asumir free tier ilimitado o permanente. SDD 9.6 define un mock determinista del proveedor LLM y advierte que puede no haber GPU, sin prometer inferencia local rápida sin medirla. SDD 14.2 exige separación entre datos reales y sintéticos; SDD 14.4 pide evaluar sesgos con datasets sintéticos controlados. SDD 16.2 prohíbe tests que dependan de un proveedor LLM pago; SDD 22 describe una demo de 5–7 minutos con CV sintético y exige seed reproducible o botón de reinicio. El roadmap Fase 11 pide perfiles ficticios variados, CV PDF/DOCX, datos incompletos, trayectorias ambiguas, contradicciones, prompt injection, etiquetas esperadas versionadas y simulación de proveedor lento, caído, tools fallidas y aprobaciones rechazadas.

## Decisión

Crear un dataset sintético versionado con etiquetas esperadas: candidatos ficticios, CV PDF y DOCX con datos incompletos, ambigüedad, contradicciones e instrucciones incrustadas como casos de prompt injection. Configurar `LLM_PROVIDER=mock` y sustitutos de correo/storage/integraciones para desarrollo, tests y demo, con seed reproducible que permita reiniciar el estado (SDD 22). Separar por completo entornos y datos demo de los datos reales: nunca CV, correos ni nombres reales en fixtures, tests, logs ni documentación; conservar procedencia y retención cuando se usen datos reales en producción (SDD 14.2). Registrar versión de dataset, prompt, modelo y resultados en cada evaluación para poder repetir el experimento y comparar regresiones (roadmap Fase 11). La simulación inyecta fallos de proveedor, timeouts y rechazos de aprobación sin contactar servicios pagos.

Esto aplica «modo demo sin credenciales pagas», «no inferir atributos protegidos» —al permitir pruebas de sesgo controladas— y «separar hechos extraídos, inferencias y datos faltantes», porque las etiquetas esperadas incluyen casos `not_found` y `needs_review`.

## Alternativas consideradas

- **Usar CV reales de prueba:** viola privacidad y minimización (SDD 14.2), contamina logs y hace la demo no reproducible.
- **Depender del sandbox de un proveedor pago:** introduce credenciales, costo, red y variabilidad; incumple RNF-017 y SDD 16.2.
- **Fixtures aleatorios sin etiquetas esperadas:** imposibilita medir exactitud, fidelidad de evidencia y regresiones entre versiones.
- **Base demo compartida con desarrollo:** un test o una demo modifica el estado de otro, rompiendo la repetibilidad exigida en roadmap Fase 11.

## Consecuencias

Positivas:

- Demo reproducible de 5–7 minutos y suite CI determinista, sin secretos ni facturación.
- Casos adversariales y de información faltante cubiertos antes de usar candidatos reales.
- Comparaciones de prompts y modelos con dataset, etiquetas y versión identificables.

Negativas:

- Los datos sintéticos no representan toda la variabilidad real; las conclusiones sobre sesgo son parciales y requieren revisión antes de uso con personas reales.
- El mock no reproduce todos los modos de fallo de un proveedor real; por eso se complementa con simulación explícita de latencia y caída.
- Mantener fixtures, etiquetas y seed exige trabajo continuo; no se asume que un free tier será permanente.
