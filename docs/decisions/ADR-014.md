# ADR-014 — Fundaciones UI/UX sin migración de router ni dependencias nuevas

Fecha: 2026-11-25
Estado: Aceptado

## Contexto

`TalentOS_UI_UX_IMPROVEMENT_PLAN.md` §21 define la Entrega A como inspección, inventario de rutas, tokens, configuración de shadcn/ui, primitives, layout base y responsive. §23 exige inspeccionar el repositorio antes de modificarlo, elaborar un inventario de gaps, proponer lotes pequeños y no agregar dependencias sin revisar mantenimiento, compatibilidad y necesidad. §24 pide diagnóstico antes de tocar código.

El inventario resultante está en `docs/ui-ux-inventory.md`. Stack real: Next.js `16.4.6` App Router, React `19.3.1`, TypeScript estricto, Tailwind `3.4.19` con variables CSS en `apps/web/src/styles/tokens.css`, Vitest + Testing Library. Hay 14 rutas root enlazadas entre sí, 27 componentes propios, un cliente HTTP en `apps/web/src/lib/api.ts`, 144 declaraciones exportadas en `apps/web/src/lib/types.ts` y 16 archivos de test verdes. No hay `components.json`, Radix, shadcn/ui, Playwright ni `packages/contracts/`.

La Fase 13 del roadmap sigue `IN_PROGRESS`: faltan E2E, revisión responsive exhaustiva y unificación total de tokens/formularios (`TalentOS_ROADMAP.md:681`). La paleta del plan (`#18181B`, `#FAFAFA`, `#E4E4E7`, `#71717A`, `#16A34A`, `#D97706`) no coincide con los tokens actuales; en particular `#E4E4E7` no alcanza 3:1 sobre superficie clara y sustituir `--color-border: #7a8794` degradaría WCAG 1.4.11.

## Decisión

1. **Conservar App Router y las rutas root existentes.** No crear prefijo `/app/*`, no cambiar de router y no renombrar rutas en esta entrega. Los enlaces de `src/app/page.tsx`, `src/app/dashboard/page.tsx`, `src/app/login/page.tsx` y `src/app/register/page.tsx` siguen válidos; cualquier migración futura necesita su propia ADR y tests.
2. **Tokens primero, hex después.** Ampliar `apps/web/src/styles/tokens.css` y su mapeo en `apps/web/tailwind.config.ts` como único punto de cambio visual. Mantener `--color-surface: #ffffff`, `--color-surface-muted: #f3f5f7`, `--color-text: #1b2430`, `--color-text-muted: #4b5563`, `--color-border: #7a8794`, `--color-accent: #0b5cad` y `--color-focus: #0b5cad` porque su contraste ya está medido. Añadir `--color-border-subtle: #e4e4e7` solo para separadores decorativos, nunca para límites funcionales. Añadir `--color-on-accent` para sustituir los 28 usos de `text-white`, y `--color-success` / `--color-warning` solo cuando exista un estado real que los consuma. No crear `--color-danger` sin caso de uso.
3. **Sin shadcn/ui ni dependencias nuevas en A1.** Mantener los 27 componentes actuales. Las primitives accesibles que se necesiten se implementarán como clases Tailwind + ARIA sobre los tokens, sin librería de estilos ni iconografía nueva. La adopción de shadcn/ui, Radix o cualquier paquete queda diferida a una ADR posterior que justifique mantenimiento, compatibilidad con React 19 y no duplicación con lo existente. Esta es una desviación temporal del criterio «componentes compartidos utilizan shadcn/ui» de §22, documentada aquí para no violar `AGENTS.md`.
4. **`layout.tsx` queda como capa global mínima.** El skip link `Saltar al contenido principal`, `main#main-content` con `tabIndex={-1}` y `lang="es"` no se modifican. El shell de workspace (sidebar, header, breadcrumbs, menú de usuario, navegación móvil) se construye como componente opt-in y se monta por rutas, no como reemplazo global.
5. **Responsive con los breakpoints por defecto de Tailwind.** `sm`/`md`/`lg`/`xl`/`2xl` ya están disponibles; no se añade framework de layout, no se adopta `next/font` y no se inventa una estrategia de tipografía sin un caso de uso medible. La navegación móvil se resolverá dentro del shell opt-in.
6. **Entrega A no se declara `DONE`.** A1 queda completada como diagnóstico. A2–A5 del inventario requieren aprobación explícita de lote y los gates `npx tsc --noEmit`, `npm run lint`, `npm test -- --run` y `npm run build`. La entrega no se cierra mientras Fase 13 permanezca `IN_PROGRESS` por E2E y responsive.

## Alternativas consideradas

- **Migrar a `/app/*` y configurar shadcn/ui en un solo cambio:** rompe enlaces y tests, añade dependencias sin evidencia y contradice §23 del plan.
- **Aplicar la paleta de §24 de forma literal:** `#E4E4E7` como borde funcional incumple WCAG 1.4.11 y `#71717A` reduce el contraste ya verificado del texto secundario.
- **No ampliar tokens:** conserva el estado actual pero deja 28 valores `text-white` y patrones repetidos sin punto central de cambio.
- **Crear `packages/contracts/` desde el frontend:** no existe hoy, el backend sigue siendo autoridad y no hay contrato nuevo que justifique la estructura.
- **Mover el shell al layout global:** afectaría a las 14 rutas, incluidas login y registro, donde la navegación de workspace no aplica.

## Consecuencias

Positivas:

- Cero dependencias nuevas y cero cambios de rutas en A1.
- Contraste medido preservado; la paleta del plan entra solo donde pase el mismo umbral.
- Diagnóstico reproducible y lotes pequeños con gates conocidos.
- `apiFetch` sigue siendo el único cliente salvo `QuestionEditor.tsx`, cuyo desvío queda registrado como deuda a corregir en A2/A3 con tests.

Negativas:

- El criterio de shadcn/ui de §22 queda pendiente de una ADR específica.
- El cambio visual percibido llega en A2+, no en A1.
- Fase 13 continúa `IN_PROGRESS`; no se reporta rediseño terminado.

## Nota de seguimiento (A4, 2026-11-25)

A4 ejecutó el shell opt-in del punto 4 sin tocar `layout.tsx` ni mover rutas: `WorkspaceShell.tsx` se monta en las 14 rutas root y sus enlaces internos son anclas absolutas a `/dashboard#...`. La home cambió «Panel» por «Ir al panel» para no duplicar el acceso del shell. Sin dependencias nuevas ni shadcn/ui (queda para ADR-015); gates web OK, 17 archivos / 97 tests, sin commit/push. A3 ejecutó después `ui/Button.tsx` sin deps, migró `LoginForm.tsx` y `DocumentUpload.tsx` y cerró con 18 archivos / 105 tests, commit `7fd464a`, CI `45699466928` success; A5 quedó verificado en ADR-015. Esta nota no modifica las decisiones anteriores.
