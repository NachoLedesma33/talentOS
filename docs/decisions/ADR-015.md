# ADR-015 — Arranque operativo de E2E con Playwright en `apps/web`

Fecha: 2026-11-25
Estado: Aceptado (decisión operativa; verificación pendiente)

## Contexto

ADR-002 ya eligió Playwright como parte del stack de calidad junto con Vitest/Testing Library. **Este ADR no re-decide el framework**: solo define cómo arrancar la suite E2E que esa decisión ya impone y que Fase 13 tiene pendiente.

`TalentOS_ROADMAP.md:681` indica que no hay suite E2E configurada y que el criterio de salida desktop/mobile de Fase 13 (`TalentOS_ROADMAP.md:677`) no está verificado; por eso la fase sigue `IN_PROGRESS`. `docs/ui-ux-inventory.md` registra el mismo gap. La Fase 13 requiere flujos principales completables sin ayuda en desktop y mobile.

Estado real del repo al redactar este ADR:

- `apps/web/package.json` ya declara `"@playwright/test": "^1.65.1"` en `devDependencies` (instalada) y el script `"test:e2e": "playwright test"`. No se añade otra dependencia ni se cambia el gestor.
- `apps/web/playwright.config.ts` y `apps/web/e2e/smoke.spec.ts` ya existen; definen `baseURL` y proyectos `desktop`/`mobile`.
- `.github/workflows/ci.yml` ejecuta en el job `frontend`: Install → Typecheck → Lint → Unit tests (`npm test`) → Build. No hay paso E2E todavía.
- No se modifica código de aplicación, tests unitarios ni contratos en esta decisión.

Nota de alcance: ADR-014 difería shadcn/ui a «una ADR posterior» y su nota de A4 menciona «ADR-015» en ese sentido. ADR-015 está reservada a E2E; la decisión sobre shadcn/ui/Radix sigue **sin aprobar** y requiere su propia ADR con justificación de mantenimiento, compatibilidad con React 19 y no duplicación. Nada de este ADR habilita esa dependencia.

## Decisión

1. **Usar la dependencia ya instalada.** Mantener `@playwright/test` `^1.65.1` como `devDependency` de `apps/web` y el script `npm run test:e2e` = `playwright test`. No instalar Cypress, WebDriver ni otro runner.
2. **Configurar `apps/web/playwright.config.ts`.** Crear ese archivo como único punto de configuración E2E. Definir `use.baseURL` desde `process.env.WEB_BASE_URL` con default `http://localhost:3000`, de modo que el mismo test corra contra `next dev`/`next start` local y contra un entorno de CI o staging sin editar specs. Los specs deben usar rutas relativas (`page.goto('/dashboard')`), nunca URLs absolutas hardcodeadas.
3. **Smoke desktop + móvil.** Los proyectos mínimos son `desktop` (viewport de escritorio) y `mobile` (viewport móvil, dispositivo con `isMobile`/touch según soporte del runner). La suite smoke cubre los flujos principales ya existentes —carga de `/`, navegación al shell de workspace y ruta representativa con API disponible— y comprueba que no hay errores de consola bloqueantes ni desbordamiento horizontal que impida completar el flujo. No se inventan rutas ni endpoints nuevos para el smoke.
4. **Orden en CI.** Añadir el paso E2E en el job `frontend` de `.github/workflows/ci.yml` **después de `Build`**, no solo después de `Unit tests`, con `npm run test:e2e` en `apps/web`. El orden real queda: Install → Typecheck → Lint → Unit tests → Build → Playwright browser → E2E. `apps/web/playwright.config.ts` usa `webServer.command: npm run start`: Playwright levanta el servidor con el artefacto ya construido, por lo que requiere `Build` previo; ejecutar E2E antes del build daría falsos negativos. El paso de navegador Playwright va después de `Build` y antes de E2E; el servidor apunta a `WEB_BASE_URL` (default `http://localhost:3000`). No se omiten los gates previos para ahorrar tiempo.
5. **Entrega A sigue `IN_PROGRESS`.** La existencia de dependencia, script, config y specs no cierra Fase 13. A5 solo se marca completada cuando el smoke pase en desktop y móvil, con evidencia de ejecución (resultado del runner) y revisión responsive verificada. Hasta entonces no se reporta Entrega A `DONE` ni se reescribe `TalentOS_ROADMAP.md:681` como resuelta. A3 permanece pendiente de aprobación.

## Alternativas consideradas

- **Cambiar de framework de E2E:** descartado; ADR-002 ya seleccionó Playwright y no hay evidencia que justifique revertir esa decisión.
- **Añadir otra librería de UI (shadcn/ui/Radix) aprovechando este ADR:** descartado; es una decisión distinta, sin justificación documentada y duplicaría componentes propios. Sigue requiriendo ADR específica.
- **Ejecutar E2E antes de los unitarios o en paralelo sin servidor:** descartado; retrasa el feedback de fallos deterministas y produce falsos negativos por `baseURL` no disponible.
- **Hardcodear `http://localhost:3000` en los specs:** descartado; rompe reutilización en CI/otro entorno y contradice el patrón de configuración por entorno del repositorio.
- **Marcar Entrega A `DONE` al crear la config:** descartado; confunde artefactos creados con comportamiento verificado y contradice el criterio de salida de Fase 13.

## Consecuencias

Positivas:

- Dependencia y script ya presentes: el cambio restante es configuración, specs y un paso de CI.
- Misma suite para local y CI mediante `WEB_BASE_URL`, sin duplicar specs por entorno.
- Cobertura mínima explícita de desktop y móvil, alineada con el criterio de salida de Fase 13.
- Estado de la entrega honesto: `IN_PROGRESS` hasta evidencia real.

Negativas:

- Requiere servidor web disponible en CI y tiempo extra de ejecución después de los unitarios.
- La verificación responsive sigue siendo parcial hasta que se revise en dispositivos reales, más allá del smoke automatizado.
- Queda pendiente resolver la referencia a «ADR-015» para shadcn/ui en ADR-014; este ADR la deja sin aprobar y no la modifica.

## Verificación (evidencia requerida para cerrar A5)

- `apps/web/playwright.config.ts` con `baseURL` desde `WEB_BASE_URL` (default `http://localhost:3000`) y proyectos `desktop`/`mobile`: creado y verificado.
- `npm run test:e2e` en local: 3 passed / 1 skipped (test móvil skip en `desktop`), con asserts responsive desktop+móvil verificados; CI: 3 passed / 1 skipped en run `45696148206` para headSha `fa8e6d9dfbaaf7478a8b8f420c5e34455a2e165b`.
- `.github/workflows/ci.yml` con orden Install → Typecheck → Lint → Unit tests → Build → Playwright browser → E2E; el paso E2E queda después de `Build`, no solo después de `Unit tests`, porque `playwright.config.ts` usa `webServer.command: npm run start` y requiere el build previo.
- Revisión responsive automatizada documentada: Chrome headless `1440x900`/`390x844` sobre `4ba7ce4`, sin overflow horizontal en `/`, `/dashboard`, `/login` y `/candidates`, menú móvil con `aria-expanded=true`, API simulada con datos sintéticos; el modelo no puede inspeccionar los PNG. Revisión en dispositivos reales pendiente. Solo entonces se podrá proponer el cierre de Fase 13 / Entrega A.
