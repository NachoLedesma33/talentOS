# ADR-006 — LangGraph para workflows con estado y aprobación humana

Fecha: 2026-11-23
Estado: Aceptado

## Contexto

El SDD 6.2 elige LangGraph para «flujos con estado, branching y aprobaciones» y el SDD 6.3 sitúa los grafos detrás del worker. SDD 9.1 manda usar IA solo para ambigüedad lingüística y código convencional para permisos, validación, cálculos, estados, persistencia y acciones deterministas; también prohíbe crear un agente autónomo por función. SDD 9.2 asigna al `Recruitment Orchestrator` seleccionar el flujo, administrar pasos, pausar para aprobación y gestionar errores, sin inventar permisos ni ejecutar acciones externas por iniciativa propia. SDD 8.3 define `AgentRun`, `AgentEvent` y `Approval` con estados `pending → running → waiting_approval → completed`. SDD 10 exige tools con contratos Pydantic, permisos por llamada, timeout, rate limit, idempotency key en escrituras y separación entre lectura, borrador y ejecución. El roadmap Fase 6 pide checkpoints, propagación de `correlation_id`, pausa/reanudación y registro de actor, fecha y decisión.

## Decisión

Usar LangGraph para grafos explícitos y acotados, con un estado tipado por workflow, nodos para los agentes especializados (`Job Analyst`, `CV Analyst`, `Matching Analyst`, `Quality Auditor`, `Recruitment Orchestrator`) y checkpoints persistidos en PostgreSQL asociados a `AgentRun`. Los puntos sensibles se modelan como interrupciones: el grafo entra en `waiting_approval`, persiste su estado y solo se reanuda cuando una API autorizada registra un `Approval` con actor, fecha y decisión. Las tools son funciones de backend con contratos Pydantic, permisos explícitos, límites de payload e idempotency key; el grafo no ejecuta SQL libre, shell, filesystem arbitrario ni acciones externas directas. Timeout, reintentos y cancelación se definen en el contrato de workflow (SDD 9.3); cada transición emite `AgentEvent` con `correlation_id` y se refleja en `AgentRun`.

Principios SDD 1.2 aplicados: «human-in-the-loop para decisiones sensibles y acciones externas», «backend como autoridad», «operaciones críticas idempotentes y auditables» y «trazabilidad».

## Alternativas consideradas

- **Máquina de estados artesanal en Python:** obligaría a reimplementar branching, checkpoints y reanudación, con mayor riesgo de perder estado al esperar aprobación.
- **Cadenas lineales tipo LangChain sin estado:** no soportan de forma natural pausa, reanudación, bucles de revisión ni trazas por nodo.
- **Agente autónomo con planificación libre:** contradice SDD 9.1 y 9.2; puede inventar permisos o ejecutar acciones externas no aprobadas.
- **Solo tareas DAG de Celery:** encaja para pasos deterministas, pero no modela aprobaciones humanas ni el estado conversacional/iterativo de los agentes; Celery sigue siendo el ejecutor (ADR-004).

## Consecuencias

Positivas:

- Un mismo run puede iniciarse, inspeccionarse, pausarse, rechazarse, reanudarse y finalizar sin perder trazabilidad (criterio roadmap Fase 6).
- Las herramientas quedan limitadas por nodo; un documento malicioso no puede ampliar permisos (SDD 14.3).
- Los checkpoints permiten reintentos y comparación de ejecuciones con versiones de prompt y modelo.

Negativas:

- Nueva dependencia y curva de conceptos (estado, nodos, interrupciones) para el equipo.
- Exige versionar el esquema de estado y los checkpoints: un cambio de grafo puede invalidar ejecuciones antiguas.
- Reanudación y duplicidad requieren pruebas obligatorias de pausa, aprobación, rechazo y ejecución duplicada (roadmap Fase 6).

## Implementación (Fase 6)

LangGraph `1.2.24`; workflow real `matching_review` v1.0.0. Persistencia en `agent_runs`, `agent_events`, `approvals` y `agent_checkpoints` (migración `0010_agent_runtime.py`). Checkpointer JSON con `thread_id = org:<organization_id>:run:<run_id>`. `interrupt()` persiste el estado en `waiting_approval`; `resume` exige `Approval` resuelta por actor autorizado y se encola en Celery. Registry de tools con permisos por rol/workflow, validación Pydantic, idempotencia, rate limit y traza sin PII. Sin acciones externas, sin autoaprobación y sin score.
