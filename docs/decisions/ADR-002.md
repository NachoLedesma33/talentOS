# ADR-002 — Next.js + TypeScript y FastAPI + Python

Fecha: 2026-11-23
Estado: Aceptado

## Contexto

El SDD 6.2 propone Next.js + TypeScript para la aplicación web, Tailwind CSS para una UI accesible consistente y Python + FastAPI para API, reglas de negocio y autorización, con Pydantic como contrato de validación, SQLAlchemy 2.x para persistencia y Alembic para migraciones. El mismo cuadro incluye LangGraph para agentes, Pytest, Vitest + Testing Library y Playwright, Ruff, mypy/pyright, ESLint, Docker Compose y GitHub Actions; el criterio de costos prioriza open source y free tiers sin asumir que serán permanentes. El SDD 5 exige validación en frontend y backend (RNF-001), autorización por operación (RNF-002) y documentación reproducible (RNF-012). SDD 6.4 añade que el frontend consume API y no accede directamente a PostgreSQL.

## Decisión

Adoptar Next.js + TypeScript en `apps/web`, con componentes accesibles y estados obligatorios de carga, vacío, error y éxito (RNF-009, RNF-010, SDD 13.4). Adoptar FastAPI + Python en `apps/api`, con Pydantic para esquemas de entrada/salida, SQLAlchemy 2.x y Alembic para la persistencia, y los contratos compartidos en `packages/contracts`. La lógica de negocio y la autorización viven en servicios de dominio del backend; el frontend solo consume endpoints y renderiza. La validación se duplica donde el SDD la pide: formularios y contratos en ambas capas. La calidad se cierra con Pytest, Vitest/Testing Library, Playwright, Ruff, mypy/pyright, ESLint, Docker Compose y CI en GitHub Actions.

El principio SDD 1.2 «backend como autoridad: el frontend nunca decide permisos» queda así reflejado en la separación de capas; también «proveedores de IA intercambiables» se apoya en que Python sea la capa que encapsula esos adaptadores (ADR-005).

## Alternativas consideradas

- **Django o Flask:** cumple la función HTTP, pero obliga a reconstruir el contrato Pydantic y la integración natural con LangGraph y el ecosistema Python de IA previsto en SDD 6.2.
- **NestJS/Node en el backend:** unifica lenguaje con el frontend, pero aleja el runtime de los agentes y añade una segunda implementación de contratos de IA.
- **API routes de Next.js como backend:** mezcla la autorización con el renderizado y difumina el límite «frontend consume API» de SDD 6.4.
- **SPA React + Vite sin Next.js:** viable, pero sustituye una convención de rutas y renderizado ya elegida en el SDD sin resolver ningún requisito del MVP.

## Consecuencias

Positivas:

- Un lenguaje por capa con tipado en ambas: errores de contrato detectables antes de integración.
- Ecosistema Python directo para Pydantic, SQLAlchemy, Pytest y LangGraph.
- Tests por capa y E2E alineados con la pirámide de SDD 16.1.

Negativas:

- Dos runtimes, dos gestores de dependencias y dos cadenas de lint/typecheck que mantener.
- Los esquemas Pydantic y TypeScript pueden divergir si no se actualiza `packages/contracts` y se ejecutan contract tests.
- No hay código de dominio reutilizable entre frontend y backend; la duplicación se limita a contratos y validación superficial.
